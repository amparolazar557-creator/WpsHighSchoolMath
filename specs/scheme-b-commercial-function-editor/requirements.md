# 方案 B：商业离线版与完整函数编辑器需求

## 范围

本版本执行建议 1、3、4：PPT 函数图像自动避让、商业离线正式发布、完整函数编辑器。Writer 的数学符号与试卷工具合并到一个 Ribbon；PPT 的数学符号与函数工具也合并到一个 Ribbon。

明确不实现建议 2：不增加符号搜索、收藏、最近使用或个性化排序。

## 功能需求

### R1：统一 Ribbon

- 当 Writer 加载插件时，系统应只显示一个名为“高中数学”的插件页签。
- 当 PPT 加载插件时，系统应只显示一个名为“高中数学”的插件页签。
- 合并后应保留当前所有符号、试卷模板、排版、函数图像和授权入口，不改变既有命令 ID。
- Ribbon XML 中不应残留第二个数学工具页签。

### R2：PPT 函数图像自动避让

- 当用户在 PPT 中插入新函数图像时，系统应读取当前幻灯片中已有形状的位置和尺寸。
- 系统应优先选择幻灯片边界内、与已有有效形状零重叠的最大候选区域。
- 当不存在零重叠区域时，系统应缩小图像并选择总重叠面积最小的候选位置。
- 系统应忽略不可见形状和覆盖整页的背景形状，并始终保留安全边距。
- 当用户更新已选中的插件函数图像时，系统应保留原图的位置和尺寸，不重新自动排版。

### R3：完整函数编辑器

- 当用户点击“函数编辑器”时，系统应优先打开可交互的 WPS 任务窗格，而不是直接进入预设确认框。
- 编辑器应支持一条或多条函数表达式、常用预设、自定义 x/y 范围、刻度数字、网格、边框和图例开关，并实时预览。
- 编辑器应支持 Writer 和 PPT；插入按钮文案应能区分“插入新图像”和“更新所选图像”。
- 当任务窗格无法完成就绪校验时，系统应自动回退到现有的原生离线快捷绘图，不留下白色空窗格。
- 编辑器及绘图引擎应完全离线运行，不依赖云服务或本地常驻服务器。若目标 WPS 禁止 `file://` 任务窗格，可在用户点击编辑器时按需启动仅监听 `127.0.0.1` 的静态页面助手；该助手不得访问外网、不得注册开机启动，并应在 15 分钟无请求后自动退出。

### R4：函数图像可重新编辑

- 系统应在插入图像的替代文字中保存带版本号的结构化绘图配置。
- 当用户选中由本插件生成的函数图像并打开编辑器时，系统应恢复表达式、坐标范围和显示选项。
- 更新图像后应覆盖旧图而不是重复插入，并写入最新配置。
- 对普通图片或旧版无结构化元数据的函数图，系统应按“新建”处理，不能误删。

### R5：商业离线发布

- 构建应生成版本化 ZIP、EXE、SHA-256 校验清单和机器可读发布清单。
- 发布清单应包含版本、生成时间、交付文件哈希、签名状态、按需页面助手和两个 WPS 插件载荷的信息。
- 构建应提供可选 Authenticode 签名参数；提供证书时必须同时签名安装器与按需页面助手并校验，未提供证书时应明确标记为“待签名”，不得伪装成已签名。
- 安装与升级应保留无关 WPS 加载项、用户机器码和授权数据，只替换本产品的 Writer/PPT 载荷与过期信任缓存。
- 商业发布校验脚本应检查版本一致性、Ribbon 单页签、编辑器载荷、安装器安全约束、哈希和签名状态。
- 当前交付保持纯离线模式；WPS 自身的首次信任确认不属于本安装包可绕过的安全边界。

### R6：双宿主安装事务与安装后校验（方案乙）

- 安装器应在修改现有安装前，分别验证 Writer 与 PPT 载荷的文件清单、SHA-256、宿主类型和启动入口；PPT 载荷不得引用 Writer 的 Ribbon 启动脚本，反之亦然。
- 两个载荷应先复制到 `jsaddons` 内的临时目录并逐文件复核，全部通过后才一起切换到正式目录。
- 安装器应备份本产品旧版目录和 `publish.xml`；任一复制、校验、注册步骤失败时，应删除未完成的新目录并恢复原目录和原注册信息，不能留下 Writer/PPT 只更新一半的状态。
- 安装成功后应再次校验正式安装目录及 `publish.xml`，输出 Writer/PPT 的版本、宿主、文件数和载荷摘要；该校验也应可由独立脚本重复执行。
- 安装事务不得删除其他 WPS 加载项，不得改写用户机器码或授权数据。

### R7：编辑器可信启动握手（方案乙）

- 按需页面助手每次启动应使用随机动态端口和不可预测的会话令牌，不再依赖 Writer/PPT 固定端口。
- 页面助手只接受带正确会话令牌路径前缀的请求；健康接口应返回产品、协议版本、构建版本和宿主角色，错误令牌应返回拒绝状态。
- 页面助手不得返回通配符 `Access-Control-Allow-Origin: *`；同源页面无需 CORS，确需从本地文件入口探测时只回显该 WPS 实际发送的 `Origin: null` 或 `file://` 本地文件源，并返回 `Vary: Origin`。
- Ribbon 只有在任务窗格页面写入与本次会话令牌一致的 ready 标记后，才可把完整编辑器判定为可用。
- 动态端口冲突、助手身份不匹配或页面超时后，系统应换端口重试一次；仍失败则隐藏任务窗格并进入原生离线绘图，且降级回调只执行一次。

### R8：正式签名闭环（方案乙）

- 商业签名构建应使用同一代码签名证书签署 Writer 载荷助手、PPT 载荷助手和最终 EXE 安装器，并为每个二进制分别记录签名状态、证书主体和 SHA-256。
- `-RequireSignature` 门禁应逐一验证安装器及 ZIP 中两个助手的 Authenticode 状态，任一缺失、无效或清单记录不一致均应失败。
- 本机没有可用代码签名证书时，可以生成明确标记为 `pending-certificate` 的内部测试包，但不得把它报告为可对外发布的已签名商业包。

### R9：正式授权中心面板

- 当用户在 Writer 或 PPT 点击“授权中心”时，系统应打开正式任务窗格，展示当前授权状态、授权类型、到期日期、剩余时间和可用范围，不再以 `alert`、`InputBox` 或 `prompt` 作为正常授权流程。
- 面板应展示只读的本机机器码，并提供“复制机器码”操作；复制成功或失败应在面板内反馈。
- 面板应提供激活码输入区、“粘贴激活码”和“立即激活”操作；无效、过期或不匹配的激活码应在面板内说明原因，成功后应立即刷新到期状态。
- 面板应展示微信二维码和 QQ 联系方式，并提供复制 QQ 操作，购买提示应明确要求发送本机机器码。
- 当到期用户点击受限功能时，系统应打开同一授权面板并显示对应功能提示；面板未打开或激活未完成前，受限功能不得继续执行。
- 离线安装路径应复用按需启动的动态回环助手加载授权面板；助手启动或就绪失败时应隐藏失败窗格并保持功能锁定，不得回退到系统激活提示框。

## 验收标准

1. 自动化测试、商业发布校验和离线构建全部通过。
2. Writer 与 PPT 各只有一个“高中数学”插件页签，既有按钮均可找到。
3. PPT 在有标题框和正文框的幻灯片中插图时，函数图像不覆盖它们；拥挤页仍在边界内并采用最低重叠方案。
4. 完整编辑器可打开、预览多函数、插入图像，并能重新载入和更新所选图像。
5. 完整编辑器加载失败时，原生快捷绘图仍可使用。
6. 发布目录包含 ZIP、EXE、checksums、release manifest 和发布说明；无证书构建清楚标记为待签名。
7. 按需页面助手仅绑定 `127.0.0.1`，只能读取插件目录，无开机启动项，升级/卸载会停止本产品所属进程。
8. 人为调换 Writer/PPT 启动文件或破坏任一载荷文件时，安装前校验必须失败；模拟安装中断时原版本与 `publish.xml` 能完整恢复。
9. 占用候选端口或启动错误服务时，完整编辑器不得误判成功；ready 超时后只出现一次原生降级流程。
10. 正式签名门禁逐一验证 EXE 安装器及 ZIP 中 Writer/PPT 两份页面助手；无证书测试包明确保持“待签名”。
11. Writer/PPT 的授权中心均可在正式任务窗格内复制机器码、粘贴并提交激活码、查看到期状态和联系方式；源码与实际流程不再调用授权专用的系统提示框。
