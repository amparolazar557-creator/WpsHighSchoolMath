# 方案 C：全插件无 localhost 的 WPS 原生化需求

状态：方案一兼容性硬门禁失败（2026-07-18，当前 WPS `12.1.0.26895` 不支持已验证的进程内原生桥接）  
目标版本：0.4.0

> 实机可行性结论：下述内容仍是用户确认的目标产品边界，但不能在当前 WPS 构建上进入正式实现。`jside FFI`、NativeX 与 COM 三条受控进程内加载路线均未通过；`validatedWpsBuilds` 必须保持为空，任务 4—18 停止。除非用户决定更换 WPS 构建或修订“零 Web 任务窗格、零外部辅助进程”的边界，否则 0.4.0 不得发布。

## 1. 背景与目标

当前完整函数编辑器和授权中心都需要由 WPS 加载项调用 `OAAssist.ShellExecute` 启动本机页面助手，再通过 `127.0.0.1` 打开 Web 任务窗格。真实 WPS 会重复创建加载项 JavaScript 上下文，导致助手复用状态丢失、反复启动 EXE，并在每次启动时显示“运行外部程序”安全警告。

用户已经把方案 C 的范围扩大为“全插件取消 localhost”。本版本的目标是：Writer 和 PPT 的正式运行链路全部改用 WPS 原生 Ribbon、输入框、确认框及文档对象接口，不再启动本地页面助手，不再监听端口，不再访问 localhost，也不再创建承载插件界面的 Web 任务窗格。

这里的“无 localhost”是指插件正式运行链路和正式发布载荷不依赖任何本机 HTTP 服务。WPS 加载项引擎从已安装目录读取自身 HTML/JavaScript 文件属于宿主加载机制，不是网络访问，仍然保留。

## 2. 范围

### 2.1 本次包含

- Writer 和 PPT 的“函数编辑器”都改为由同一签名 DLL 提供的 Windows 进程内原生编辑面板。
- 数学符号、函数工具、试卷工具和授权中心继续放在同一个“高中数学”Ribbon Tab 内，通过分组区分，不拆成多个 Ribbon Tab。
- 函数编辑器支持一个或多个函数表达式、自定义 x/y 范围及刻度数字、网格、边框、图例四项显示设置。
- 保留 Writer/PPT 插入新图像、载入所选函数图像配置、更新所选图像及配置元数据。
- 保留 PPT 自动避让标题框、正文框和其他已有形状的放置逻辑。
- 保留本地 SVG 生成、临时文件清理和离线授权校验。
- Writer 和 PPT 的授权中心改为同一“高中数学”Ribbon 内的 WPS 原生授权区。
- 原生授权区提供授权状态、授权类型、到期日期、剩余天数、机器码、QQ `982303035` 和微信号 `qzt65631`。
- 原生授权区提供“打开授权中心”入口；签名 DLL 显示正式 Windows 原生面板，集中展示机器码、到期状态、QQ `982303035`、微信号 `qzt65631`，并提供复制机器码、粘贴/输入激活码和复制联系方式。
- 在通过任务 2 门禁的 WPS 构建上，Writer/PPT 的 JavaScript 应通过已实测可用的 WPS 官方 `jside FFI` 以绝对路径加载同一份签名 x86 DLL；DLL 只负责原生界面与临时返回值，授权校验、授权存储、绘图和文档写入仍由现有 JavaScript 领域模块负责。当前构建不满足此前提。
- 删除正式运行链路中的函数编辑器 Web 页面、授权中心 Web 页面、任务窗格调度器和本地页面助手。
- 构建、安装、升级、卸载和商业发布验证同步改为零 localhost 模式。
- 为 0.3.x 已安装用户提供一次性迁移桥，在旧插件自身可访问的存储上下文中仅导出本产品授权字段；0.4.0 安装器只有在导出文件校验成功后才替换旧版。
- 从旧版升级时停止遗留页面助手进程，并清除旧发布载荷中的助手 EXE 和网页面板文件。

### 2.2 本次不包含

- 不保留函数编辑器 Web 任务窗格中的实时图像预览；用户确认配置后才生成并插入或更新图像。
- 不保留授权中心 Web 侧边面板。
- 不新增开机启动项、Windows 服务、常驻后台程序、外部辅助 EXE、仅 Writer 可用的 WLL 加载项或云服务；正式载荷只新增一份经 Authenticode 校验的进程内原生桥接 DLL。
- 不改变数学符号、试卷工具、授权规则、激活码格式、试用期规则和机器绑定规则。
- 不把微信二维码作为 Ribbon 内必须展示的大图；联系方式以 QQ `982303035`、微信号 `qzt65631` 及各自复制按钮为正式入口。
- 不复制、解析或修改 WPS 全局 Chromium Local Storage/LevelDB 数据库；迁移只处理本产品明确定义的键和值。

## 3. 用户故事

1. 作为教师，我希望打开插件及使用任意功能时都不再确认运行外部程序，也不受端口占用影响。
2. 作为教师，我希望点击“函数编辑器”后直接打开一个完整的 Windows 原生编辑面板，并可一次输入多条函数、设置范围和显示选项。
3. 作为教师，我希望选中以前插入的函数图像后重新编辑，原配置自动成为默认值，确认后原位更新。
4. 作为 PPT 用户，我希望新插入图像继续自动避让幻灯片已有内容。
5. 作为用户，我希望直接在“高中数学”Ribbon 查看授权摘要，并可通过“打开授权中心”进入正式原生面板，复制机器码、粘贴激活码、查看到期状态以及 QQ 和微信号。
6. 作为旧版 WPS 用户，我希望原生自定义输入不可用时仍能用常用函数快速绘图，而不是出现白窗格或无响应。

## 4. 功能需求与验收标准

### R1. 全插件零 localhost

- 当 WPS 加载插件、打开文档、点击任意 Ribbon 控件、触发授权门禁或显示到期提醒时，系统不得调用 `OAAssist.ShellExecute` 启动插件辅助程序。
- 当插件运行时，系统不得创建或连接 `localhost`、`127.0.0.1`、`::1` 或其他本机 HTTP 地址。
- 当插件运行时，系统不得创建 HTTP/TCP 监听器，不得启动 `WpsHighSchoolMathEditorHost.exe` 或同类辅助进程。
- 当插件显示函数编辑器、授权中心或错误信息时，系统不得调用 `Application.CreateTaskPane`、`Application.ShowDialog` 或其他 Web 容器承载插件页面。
- 当用户连续打开函数编辑器、查看授权状态或激活时，WPS 不应显示“运行外部程序”安全警告。
- 正式 Writer/PPT 发布载荷和安装后的插件目录不得包含页面助手 EXE、函数编辑器网页、授权中心网页或任务窗格调度脚本；只允许白名单内且签名、哈希、架构均通过验证的原生桥接 DLL。

### R2. 进程内原生函数编辑面板

- 当进程内桥接能力可用时，系统应在同一个模态原生面板中收集函数表达式、x 范围、y 范围和显示选项。
- 当用户输入多条函数时，系统应接受中文分号、英文分号或换行作为分隔符。
- 当用户输入无效表达式、无效数字或最小值不小于最大值时，系统应显示明确错误，并且不得修改文档。
- 当用户取消面板时，系统应立即结束流程，并且不得插入、更新或删除文档内容，也不得保留未提交草稿。
- 当用户编辑已选中的函数图像时，系统应以图像中保存的表达式、范围和显示选项作为各步骤默认值。
- 当用户在面板中确认时，DLL 应只返回版本化 JSON 配置；JavaScript 复验通过后才生成并写入图像。

### R3. 绘图与显示选项

- 当用户确认配置时，系统应使用现有离线绘图引擎生成 SVG。
- 系统应支持刻度数字、网格、边框和图例分别开启或关闭。
- 系统应继续支持现有表达式语法，包括四则运算、幂、隐式乘法和现有三角、根式、绝对值、对数及指数函数。
- 当生成过程中发生错误时，系统应显示具体错误，不得留下损坏图像或临时文件。

### R4. Writer 插入与更新

- 当 Writer 中没有选中已有函数图像时，系统应在当前光标位置插入新图像。
- 当 Writer 中恰好选中一个带有效函数配置的图像时，系统应原位更新该图像并保留合理尺寸。
- 当插入或更新成功时，系统应把完整配置写入图像元数据，以便后续重新编辑。
- 当更新过程中生成或插入新图像失败时，系统应保留原图像和原配置，不得先删除旧图造成内容丢失。

### R5. PPT 插入与更新

- 当 PPT 中没有选中已有函数图像时，系统应在当前幻灯片中插入新图像，并继续采用现有内容避让算法。
- 当 PPT 中恰好选中一个带有效函数配置的图像时，系统应原位更新并保持其位置和尺寸。
- 当幻灯片空间拥挤时，系统应继续选择边界内重叠最小的位置，而不是覆盖页面外或直接失败。
- 当更新过程中生成或插入新图像失败时，系统应保留原图像、位置和尺寸。

### R6. WPS 原生授权中心

- Writer 和 PPT 的“高中数学”Ribbon 应各包含一个原生“授权中心”分组，不再只保留一个打开网页面板的按钮。
- 当 Ribbon 获取授权信息时，系统应动态显示“试用中、已激活或已到期”、授权类型、到期日期、剩余天数和当前功能权限。
- 系统应在授权区显示完整机器码，并提供“复制机器码”按钮。
- 系统应在 Ribbon 提供“打开授权中心”按钮；当用户点击该按钮时，系统应通过已验证的 `jside FFI` 桥接器打开签名 DLL 提供的正式原生授权面板。面板必须允许 `Ctrl+V` 粘贴激活码，并提供复制机器码、复制 QQ、复制微信号以及关闭/取消操作；不得调用浏览器 `prompt()`、WPS Web 对话框或外部程序。
- 当用户取消或关闭原生授权面板时，系统不得校验、写入、清空或刷新任何授权状态，也不得把已输入内容保存为草稿。
- DLL 不得校验或持久化激活码；它只把用户明确确认的码值临时返回给当前 JavaScript 调用栈，返回后立即清空 DLL 内部缓冲区。
- 当激活成功且共享状态回读成功时，系统应刷新 Writer/PPT Ribbon 的状态、到期日和剩余天数；当激活失败时，系统应显示具体原因并保留原有授权，不得把失败的激活码写入日志、状态文件、宿主存储或持久草稿。
- 当激活码格式错误、机器不匹配、签名错误或已过期时，系统应显示具体原因，不得覆盖已有有效授权。
- 系统应显示 QQ `982303035` 并提供“复制 QQ”按钮。
- 系统应显示微信号 `qzt65631` 并提供“复制微信号”按钮。
- 当剪贴板写入失败时，系统应保持机器码、QQ 和微信号在 Ribbon 中可见，并明确提示用户可手动复制。
- 当激活成功时，系统应把有效激活码保存到 Writer 和 PPT 共用的离线授权状态文件；重新启动 WPS 或切换宿主后，两个插件应读取同一授权结果。
- 共享 A/B 授权状态应使用 `FileSystem.writeAsBinaryString()` 和 `FileSystem.readAsBinaryString()` 按完整固定 AppData 路径读写；逻辑 JSON 应先编码为 UTF-8，再封装为带固定版本前缀的 Base64 ASCII 数据，不得使用 `writeFileString()`、`readFileString()` 或诊断性 `WriteFile()/ReadFile()` 作为正式读写路径。
- 每个槽的逻辑 JSON UTF-8 原始数据不得超过 12,000 bytes，包含固定前缀、Base64 和全部元数据的完整 ASCII 封套不得超过 16,384 bytes；系统应在写入前同时校验两个上限，并在读取后先校验物理上限、解码后再校验逻辑上限。任一超限都应拒绝该候选，并保持原权威槽不变。
- 当从 0.3.x 升级且旧版在完整冷启动后仍能识别有效激活码时，一次性迁移桥应先把该激活码导出到本产品固定状态文件；0.4.0 应迁移该授权，不得要求已购用户重新激活。
- 当迁移导出缺失、损坏、机器不匹配或无法验证时，0.4.0 安装器应在替换旧版前停止升级并保留旧版本，不得通过扫描 WPS 全局浏览器数据库或重新启用 localhost 猜测恢复。

### R7. 授权门禁与提醒

- 当授权有效时，现有付费功能门禁行为保持不变。
- 当授权无效且用户点击付费功能时，系统应阻止该功能，并通过简短原生提示引导用户前往同一 Ribbon 的“授权中心”，不得打开任务窗格或启动辅助程序。
- 当授权到期或剩余 7、3、1 天时，系统可每日最多显示一次简短原生提醒，同时授权区动态状态必须始终是权威信息来源。
- 当授权状态发生变化时，Writer 和 PPT 应在各自下一次刷新或启动时显示一致状态。

### R8. 兼容与降级

- 当 WPS 不提供可用的 `jside FFI`、DLL 无法加载、签名不可信或桥接协议版本不匹配时，系统应进入现有离线快捷选择流程。
- 当快捷选择流程运行时，系统应至少支持 `x^2`、`1/x`、`sin(x)` 和 `cos(x)`。
- 当用户取消快捷选择时，系统不得修改文档。
- 正式安装包只允许安装到已分别通过 Writer/PPT `jside FFI` 进程内 DLL 加载、原生面板输入/取消流程与 `writeAsBinaryString()/readAsBinaryString()` 完整路径共享文件实测、并列入发布清单的 WPS 构建号。
- 当当前 WPS 构建号未验证、DLL 位数或签名不匹配、桥接器无法在任一宿主完成输入/取消流程，或未通过二进制共享文件读写门禁时，安装器应在替换现有插件前停止安装、保留原版本并显示明确的版本不兼容说明，不得先装入正式载荷再尝试运行时隐藏。
- 仓库可保留一份本机诊断恢复 Ribbon，用于在兼容性测试失败时显示授权状态、机器码、QQ 和微信号；它不得进入正式商业载荷，也不得提供激活码输入按钮。
- 任何降级路径都不得启动本地 EXE、访问 localhost 或创建 Web 任务窗格。

### R9. 构建、升级与回归门禁

- 自动化测试应覆盖 Writer/PPT 原生函数入口、多函数、范围、显示选项、取消、错误、插入、事务式更新和旧版降级。
- 自动化测试应覆盖授权状态标签、原生 DLL 确认与取消、成功激活、失败不覆盖、复制机器码、复制 QQ、复制微信号和 Ribbon 刷新。
- 正式改造开始时应先在当前 WPS Writer/PPT 上验证 Ribbon 按钮通过 `jside FFI` 加载同一 x86 DLL、DLL 运行于各自 WPS 进程内、完整粘贴与返回、取消无副作用，以及二进制 API 的完整路径覆盖截断、立即回读、边界大小、A/B 恢复和跨宿主共享；仅在全部通过后，把该构建列入正式支持白名单。
- 2026-07-16/17 已形成的 `editBox.onChange`、WPS `InputBox` 与旧字符串文件 API 失败记录应作为历史兼容性证据保留；它们不再是方案一的新硬门禁，也不得被改写为通过记录。
- 安装与发布验证应确认当前 WPS 构建号存在于实机验证白名单；未验证构建必须在载荷切换前拒绝安装，且失败路径不得破坏现有版本。
- 发布验证应拒绝正式 Writer/PPT 载荷中的 `openLocalEditor`、`ShellExecute`、`CreateTaskPane`、回环 URL、页面助手二进制和 Web 编辑器/授权页面。
- 构建脚本不得再编译、签名或复制 `WpsHighSchoolMathEditorHost.exe`，不得再生成函数编辑器或授权中心的版本化网页副本。
- 0.3.x → 0.4.0 升级测试应覆盖一次性迁移桥导出、Writer/PPT 冷启动后授权恢复、导出损坏时拒绝升级，以及全程不读取其他加载项的浏览器存储。
- 安装器应继续识别旧版本，并在升级时停止遗留助手进程、删除旧助手文件和旧网页面板文件；清理完成后不得安装新的辅助运行时。
- Writer 与 PPT 实机回归应确认：启动、函数编辑、授权查看、复制和激活均无外部程序警告，且任务管理器中没有插件辅助进程。
- 实机回归应确认插件运行期间没有本机监听端口，也没有对 `localhost`、`127.0.0.1` 或 `::1` 的连接。

## 5. 原生交互方向

### 5.1 函数编辑器

- 交互形式：签名 DLL 提供的单个 Windows 模态原生面板，不创建 WebView 或任务窗格。
- 面板同时展示表达式、x/y 范围和四项显示设置；默认值来自新建默认配置或当前所选图像配置。
- 用户确认后只返回配置，不直接操作 WPS 文档；JavaScript 负责校验、绘图和事务式插入/更新。

### 5.2 授权中心

- 交互形式：同一“高中数学”Ribbon 内保留授权摘要与“打开授权中心”按钮；按钮打开签名 DLL 提供的正式 Windows 原生面板，不再是 Web 侧边面板。
- 信息区：状态、授权类型、到期日期、剩余天数、机器码、QQ `982303035`、微信号 `qzt65631`。
- 操作区：复制机器码、粘贴/输入激活码、复制 QQ、复制微信号、确认激活和取消；取消不改变状态。
- 状态更新：激活后调用 Ribbon 刷新，使所有动态标签立即重新读取授权核心状态。
- 状态持久化：使用 WPS 本地文件接口保存一份 Writer/PPT 共享的签名激活码，继续完全离线运行。

### 5.3 样式覆盖说明

- 视觉风格完全继承 WPS/Windows 的 Ribbon、输入框、按钮和提示框。
- 由于用户明确要求全插件无 localhost，本版本不使用 Web CSS、自定义字体或网页图标系统。
